# Midnight Blue Dark Mode Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task in this session.

**Goal:** Deliver the approved app-wide midnight blue theme without disrupting local-first editing.

**Architecture:** A small root ThemeProvider owns browser preference and resolved appearance. A synchronous head initializer sets the root data attribute before rendering; shared semantic CSS tokens theme the application, while CodeMirror receives its resolved theme without remounting.

**Tech Stack:** Existing Next.js, React, TypeScript, CSS variables, Vitest, and Playwright; no added dependencies.

**Spec:** `docs/superpowers/specs/2026-09-17-dark-mode-design.md`

## Global constraints

Continue on `codex/dark-mode-plan`; preserve light mode and document data. No migration, deployment, or merge. Theme storage is browser-wide, separate from workspace data. Use existing fonts, illustrations, and layout.

## 1. Preference lifecycle

- [x] Add `src/lib/theme.ts`: `ThemePreference = "light" | "dark" | "system"`, `ResolvedTheme = "light" | "dark"`; `initializeTheme()` reads and validates browser storage, resolves the device setting, writes `html.dataset.theme`, and returns both values. Its serialized function is the pre-paint script.
- [x] Add `src/components/mdez/ThemeProvider.tsx`: expose `useTheme()` with preference, resolved theme, and `setPreference(preference)`. Listen to device and storage events with cleanup; storage failures remain session-local.
- [x] Integrate the initializer and provider in `src/app/layout.tsx` with narrowly scoped root hydration suppression.
- [x] Test missing/invalid preferences, unavailable storage, device changes, overrides, cross-tab changes, and bootstrap execution in `tests/unit/theme.test.tsx`.

## 2. Accessible chooser
